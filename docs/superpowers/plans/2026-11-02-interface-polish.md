# 工作志界面优化实施计划

**目标：** 按用户选择的“清爽办公：浅色界面、深绿点缀”，在现有 React / CSS 实现上统一界面。

**范围：** 公共导航、登录、基础控件、日志与批注、后台表格、统计卡片。沿用现有接口、角色、日志颜色语义和业务流程，不加依赖，不改数据库，不覆盖已有功能修改。

**设计：** 浅灰工作区、白色侧栏与面板、深绿主操作；正文 14px，辅助文字至少 12px；面板减少阴影，表单和表格保持清晰分隔。按用户补充要求，日志保留信纸格式：米白纸面、32px 横线、深绿表头、逐项编号、左侧工作内容、右侧批注，以及右下角姓名和日期签署区。手机导航横向滚动，表格在容器内滚动，信纸内容与批注上下排列，打印保持双栏。

**取舍：** 保留现有组件和页面结构；不引入另一套组件库，不增加深色模式。以共享样式修正为主，避免逐页重建。

- [x] 为中文角色、跳转正文入口和提醒菜单 Esc 关闭及焦点返回补充最小回归断言。
- [x] 更新 AppShell 和统一 SVG 图标，保留角色导航与退出登录。
- [x] 在 styles.css、employee.css、admin.css 统一视觉及响应布局，整理登录和页面标题；用户列表前置，角色和日志状态显示中文。
- [x] 运行前端单测、类型检查及构建；用本地测试数据在 1440、768、390px 检查页面、焦点、提醒和横向溢出。

**验证边界：** 浏览器验证使用隔离的模拟 API，不向真实系统写入测试数据；交付本地改动，不部署服务器。

**验证结果：** 29 项前端测试通过；`pnpm typecheck`、`pnpm build`、`git diff --check` 通过。Playwright 在生产构建上检查 15 个页面 × 3 个宽度，无整页横向溢出及运行时错误，并检查注册入口、输入框焦点、提醒弹层边界、Esc、空列表、禁用分页和加载失败。信纸检查覆盖填报、补写、员工详情、主管详情和待审页面，验证纸色、横线、双栏/单栏与签署区；打印媒体检查验证保留双栏、批注表头并隐藏导航。截图与检查脚本位于 `work/ui-preview/`、`work/ui-preview.cjs`。打印仅验证浏览器媒体样式，未连接物理打印机。

**设计检查：** Impeccable detector 无发现；tasteskill 生产登录页检查 0 FAIL、5 WARN。保留原有 WORKLOG 字标及登录页深绿色品牌区，因此通用应用屏幕检测仍提示字标大小、颜色占比、品牌区留白、宣传标题大小和手机辅助文字比例。工作区采用浅色界面，登录页保持品牌展示用途。独立 UI 复核未发现重要回归。
