# 员工工作日志管理系统正式版设计规格

日期：2026-10-10

## 1. 建设目标

将现有浏览器本地演示版升级为可在 Linux 云服务器上长期运行的正式系统，为 50 人以内的项目研发型公司提供每日工作日志、系统内提醒、多级审批、红灰状态管理、周期统计、奖惩确认和完整操作追踪。

正式版不包含项目管理、任务领取和数字评分。员工只负责填写每日工作日志；领导通过红色或灰色评价完成情况。

## 2. 部署环境

- 服务器系统：Linux。
- 当前访问地址：公网 IP `101.132.147.80`。
- 初期访问方式：通过公网 IP 访问。
- 正式投入使用前建议绑定域名并启用 HTTPS。
- 用户规模：首期 50 人以内。
- 部署方式：Docker Compose。

## 3. 技术架构

采用 Node.js 单体应用、PostgreSQL、Nginx 和 Docker Compose：

- Nginx 作为公网访问入口，转发应用请求并实施基础访问限制。
- Node.js 应用同时提供业务接口、身份认证、权限校验、页面服务和定时任务。
- PostgreSQL 保存所有正式业务数据和审计记录。
- Docker Compose 统一管理应用、数据库和 Nginx 容器。
- 定时任务检查未提交日志并生成系统内提醒。
- PostgreSQL 只在容器内部网络开放，不向公网暴露端口。

数据流：员工登录并提交日志 → 日志显示绿色 → 对应领导当天核查并选择红色或灰色 → 后续审批人依次复核 → 日志归档 → 员工查看结果 → 数据进入周期统计和奖惩确认。

## 4. 角色与权限

### 4.1 员工

- 登录和修改本人密码。
- 填写、暂存、提交和修改被退回的本人日志。
- 查看本人日志的绿色、红色或灰色状态。
- 查看审批意见、审批进度、退回意见和历史日志。
- 查看本人红灰统计和按时提交情况。
- 不得查看其他员工日志，不得设置或修改颜色。

### 4.2 直属领导和审批领导

- 查看管理员授权范围内员工的日志。
- 在员工提交当天核查日志。
- 选择红色或灰色并填写审批意见。
- 退回日志并填写退回原因。
- 按配置顺序执行多级审批。
- 修改权限范围内已核查日志的颜色，修改时必须填写原因。
- 查看授权部门和员工的统计结果。

### 4.3 管理层

- 查看公司全部日志及部门、员工统计。
- 查看月度、季度和年度汇总。
- 确认奖励、改进或处罚结果。
- 查看相关操作记录。

### 4.4 系统管理员

- 管理员工、领导、管理层账号和部门。
- 创建账号、设置初始密码、停用账号和重置密码。
- 配置员工的一个或多个审批人及审批顺序。
- 设置每日提交截止时间和提前提醒时间。
- 查询全部日志、提醒和审计记录。
- 管理系统基础配置。

## 5. 账号与认证

- 账号由管理员创建，并设置用户名和初始密码。
- 用户首次登录后必须修改初始密码。
- 密码采用适合生产环境的不可逆密码哈希保存，数据库不保存明文密码。
- 连续登录失败达到限制后，账号临时锁定。
- 登录会话设置有效期，退出登录后会话立即失效。
- 停用账号不得继续登录，但其历史日志和审计记录必须保留。

## 6. 每日工作日志

每名员工每天最多创建一篇正式日志。日志包括：

- 日志日期。
- 按 1、2、3 排列的工作事项。
- 每项工作的内容和完成情况。
- 未完成原因，未完成时必填。
- 备注。
- 次日计划。
- 草稿、已提交、审批中、已退回和已归档状态。
- 提交时间及是否按时提交。

员工提交成功后，日志自动显示绿色“已提交，待核查”。员工不能自行设置红色或灰色。

## 7. 审批与颜色规则

- 绿色：员工已提交，等待领导核查。
- 红色：领导确认工作已完成。
- 灰色：领导确认工作未完成或逾期。
- 系统不设置数字评分。

管理员可为每名员工配置一个或多个审批人。审批人必须按配置顺序处理日志。每一步记录审批人、颜色、审批意见和审批时间。

审批人可退回日志。员工修改后重新提交，系统保留退回前的日志内容、退回意见和重新提交记录。

有权限的领导可修改已核查日志的红色或灰色状态，但必须填写修改原因。系统记录修改前颜色、修改后颜色、修改人和修改时间。

## 8. 系统内提醒

- 管理员配置每日提交截止时间和提前提醒分钟数。
- 截止前向尚未提交的员工生成系统内提醒。
- 截止后向未提交员工生成逾期提醒，并在对应领导的工作台显示未提交信息。
- 新审批任务、日志退回和审批完成均生成系统内提醒。
- 用户可标记提醒为已读。
- 第一阶段不接入短信、邮件、企业微信或钉钉。

## 9. 统计与奖惩

系统支持按员工、部门和公司统计：

- 应提交、已提交和未提交日志数量。
- 绿色待核查、红色完成和灰色未完成数量。
- 按时提交率。
- 工作完成率，计算方式为红色数量除以红色与灰色数量之和。
- 退回次数。

统计周期包括月度、季度和年度。奖惩建议只依据红色、灰色和完成率产生，不使用数字评分。建议结果仅供参考，最终奖励、改进或处罚由有权限的领导确认并记录确认意见。

## 10. 查询功能

- 员工按日期查询本人历史日志。
- 领导按员工、部门、日期和颜色查询授权范围内日志。
- 管理层和管理员查询全部日志。
- 审计记录可按操作者、员工、操作类型和时间范围查询。
- 查询结果默认分页，避免一次加载全部历史数据。

## 11. 数据模型

正式版至少包含以下数据实体：

- 用户、角色、部门和账号状态。
- 员工审批关系和审批顺序。
- 工作日志和日志事项。
- 日志版本和重新提交记录。
- 审批步骤和审批意见。
- 颜色修改记录。
- 系统内提醒和已读状态。
- 周期奖惩确认记录。
- 登录会话和登录失败记录。
- 操作审计记录。
- 系统设置。

数据库使用外键、唯一约束和事务保证数据一致性。员工与日期组成唯一约束，防止同一天重复创建正式日志。

## 12. 安全与审计

- 所有业务接口同时校验登录状态和角色权限。
- 员工只能访问本人数据；领导只能访问授权范围内数据。
- 对用户名、日志内容、意见和查询条件进行格式与长度校验。
- 防止 SQL 注入、跨站脚本、跨站请求伪造和暴力登录。
- 登录接口实施速率限制。
- 数据库不向公网开放。
- 创建、提交、修改、退回、审批、改色、账号变更、配置变更和奖惩确认全部写入审计记录。
- 已归档日志不得直接覆盖或无记录删除。

## 13. 备份与运维

- PostgreSQL 每日自动备份，保留最近 30 天。
- 备份文件保存到服务器受限目录；条件允许时增加异机备份。
- Docker 容器随服务器重启自动恢复。
- 应用错误、异常登录和备份失败写入运维日志。
- 提供数据库恢复操作说明，并在上线前完成一次恢复演练。
- 升级前执行数据库备份，数据库结构变更通过版本化迁移完成。

## 14. 错误处理

- 登录失败、权限不足、重复提交和审批顺序错误返回明确提示，不暴露服务器内部信息。
- 数据库事务失败时回滚整次业务操作。
- 定时任务失败记录错误并允许下次重试，不重复创建同一提醒。
- 前端提交按钮在请求处理期间禁用，防止重复提交。
- 网络错误时保留用户尚未提交的表单内容并提示重试。

## 15. 页面范围

### 员工端

- 登录和首次修改密码。
- 今日工作日志。
- 被退回日志修改。
- 历史日志和审批结果。
- 个人统计。
- 系统内提醒。

### 领导端

- 待审批列表和日志详情。
- 退回、红灰定色和多级审批。
- 已审批日志和颜色修改。
- 员工日志查询。
- 部门统计和未提交提醒。
- 系统内提醒。

### 管理层和管理员端

- 公司统计和周期汇总。
- 奖惩确认。
- 用户、部门和审批关系管理。
- 提交及提醒设置。
- 全部日志查询。
- 审计记录查询。

## 16. 测试与验收

测试包括：

- 业务服务单元测试。
- 数据库约束和事务集成测试。
- 登录与角色权限测试。
- 员工提交、退回、重新提交和多级审批流程测试。
- 红灰状态修改和审计测试。
- 提醒去重与截止时间测试。
- 月度、季度和年度统计测试。
- 关键页面桌面端和移动端浏览器测试。
- Docker 部署、数据库备份和恢复测试。

正式版验收条件：

- 真实账号登录和权限隔离生效。
- 所有业务数据写入 PostgreSQL，刷新浏览器或更换设备后数据不丢失。
- 员工可完成每日提交并查看红灰结果。
- 多级审批顺序、退回和改色规则正确。
- 系统内提醒按设置生成且不重复。
- 统计和奖惩参考数据与日志结果一致。
- 关键操作可追踪。
- Linux 服务器重启后服务自动恢复。
- 已验证每日备份和至少一次数据库恢复。

## 17. 明确不在第一期范围内

- 项目管理和任务领取。
- 数字评分。
- 手机短信、邮件、企业微信和钉钉通知。
- 手机原生应用。
- 第三方单点登录。
- 工资系统自动发放奖金或执行处罚。
