# 静态扫描报告逐项核对与整改设计

日期：2026-10-21

## 目标与基线

用户要求逐项核对 `worklog_export.tar.gz` 的 185 条未解决问题，修复当前源码中确实有效的问题。整改应保持现有日志提交、审批权限、计划到期、审计和部署行为。报告是静态扫描快照；最终结论以当前发布源码及运行验证为准。

当前发布源码位于 `work/release-audit-fixes-20261019`。根目录存在此前工作产生的未提交改动，不能用报告中的行号直接编辑根目录或覆盖这些改动。每条问题以规则、路径、代码位置和当前实现重新匹配。

## 核对结果的记录方式

建立一份逐项台账，保留报告原始问题编号、规则、文件、行号、当前对应位置、处置（修复／无需修改／已不存在）及理由。相同规则可采用一致的修法，但每个编号均有独立结论。修复后复查台账对应代码，并用测试、构建或页面检查证明结果。

## 处理范围

1. **产品代码和样式：** 对表单按钮补充正确的 `type`；对 `FormData` 和 `FileReader` 结果做符合实际类型的处理；修复 Promise 拒绝值、键盘交互及无障碍语义；整理复杂条件表达式、重复导入和冗余类型／语法。保持 API 数据格式及审批规则不变。
2. **CSS：** `theme.css` 的 38 条重复选择器源于先后叠加的两套主题。合并确认可安全合并的规则，保留当前页面的最终视觉效果；修正实际生效的文本／背景对比度。合并前后比较主要角色页面及窄屏布局。
3. **测试代码：** `appendAudit` 的空异步实现位于内存测试仓库，并非生产审计实现。将其改为可观察的测试行为，避免测试误以为审计已保存。其余测试代码告警在不改变测试意图的前提下清理。
4. **Prisma 生成代码：** 27 条 `S7724` 来自生成器写入的全局 ESLint 禁用声明。生成结果不手工编辑；在扫描配置中排除生成目录，或在扫描平台标记为生成代码。如果当前项目没有受控扫描配置，台账说明需在 Sonar 扫描任务配置该排除项。
5. **条件跳过的验收测试：** 7 条 `S1607` 由 `E2E_RUN` 或验收账号缺失触发，代码已写明跳过原因。保留其门槛，在台账标为有意设计。
6. **代理网段：** 3 条 `S1313` 指向同一行私网 CIDR。Compose 未将 app 端口发布到主机；Nginx 是公开入口，app 通过 Docker 内网接收转发。保留当前信任网段，并在台账记下网络边界和若将来单独暴露 app 端口需重新评估的条件。

## 实施与验证

先按风险处理真实输入和交互问题，再处理样式与机械化清理。新增或调整覆盖图片读取失败、表单提交意图、关键键盘操作和对比度的针对性检查；运行相关 Vitest、完整 `pnpm verify`，并检查主要页面。不会为了迎合规则把生成文件或已有意图的环境跳过测试改成难维护的手工代码。

项目未发现随源码受控的 Sonar 配置，且报告只提供问题快照。若扫描平台不可访问，台账将明确“源码已验证”和“扫描状态未复核”的区别。部署仅使用已通过验证的发布源码，并在操作前核对服务器当前版本及回滚材料。

## 风险控制

CSS 合并和无障碍语义变更可能影响布局或键盘操作，需页面检查。`FormData` 和图片结果处理不应把空值转成字面量 `"null"` 或 `"[object Object]"`；无效输入应显示既有错误提示。任何涉及代理或审批行为的变更必须先验证网络或业务条件，不能仅凭扫描严重度修改。
