# 员工日志每周归档设计

用户要求每周一次导出上一自然周全部员工工作日志并交付 ZIP，已选择现有私有 OSS 保存 365 天、本地仅临时处理。

采用服务器 systemd timer，每周一 09:00 Asia/Shanghai，Persistent=true；首次试跑 2026-10-26 至 2026-11-01。按 daily_logs.work_date 半开区间 [上一周周一, 本周周一)，读取执行时刻一致性快照，包含所有状态和颜色，以及正文、原始图片 dataUrl、版本、审批、批注回复、颜色调整、档案事件、相关提醒与业务审计；另含该周免交记录和关联人员最小信息。图片以原始字段保存在完整 JSONL，CSV 提供不含大图片/快照字段的可读索引，并防止 Excel 公式注入。独立工作计划不在此次员工工作日志数据范围内。

ZIP 名称 employee-logs_YYYY-MM-DD_to_YYYY-MM-DD.zip，OSS 前缀 worklog/weekly-employee-logs/。同时交付 ZIP.sha256 和 ZIP.receipt.json。完整 ZIP 只在 OSS 存放，不在服务器磁盘落地。PG 导出快照与 COPY 流保持只读一致性，逐文件计数及 SHA-256；ZIP 内含 manifest.json 和 SHA256SUMS。上传采用带完成尾帧的流：源导出失败或记录数不符时不允许完成上传；上传成功后下载流核对整包 SHA-256，再发布回执。

不覆盖已验证的同名归档；重跑先验证后跳过。导出后的迟到补写/审批不自动修改已发布快照，允许指定历史周加 --revision 重新导出并保留旧包。空周也生成含零计数的有效 ZIP。失败返回非零并记录结构化运行状态；锁防止同机重叠。

独立的每日 02:15 Asia/Shanghai 定时任务执行清理。保留期按对象最后修改时间满 365 天计算，只清理此前缀、名称匹配且带本工具格式标识的 ZIP 及其配套回执，不删除数据库日志或原有逐条档案。使用现有 ECS RAM 实例角色，不导出凭据，不自动扩大 IAM 权限；启用前以自建临时探针验证上传、读取和删除能力。缺少权限时交付最小前缀策略并报告未完成，不虚报定时已启用。

比较：仅服务器文件加 cron 最简单但磁盘已用约 93%；在应用一分钟轮询器内打包会增加服务负担并依赖应用重启。服务器独立 timer + 流式脚本复用 psql/Python/现有 ali-oss，无需重编译应用，因此选用此方案。

约束：不改数据库结构，不迁移/删除在线业务数据，不读取或输出 .env 密钥，不接入未指定的第三方交付渠道，不把业务状态当 INFO/WARN/ERROR。任务运行日志记录 INFO/WARN/ERROR，但不记录员工正文或附件。
